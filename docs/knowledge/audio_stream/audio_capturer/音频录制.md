# 音频录制

## 范围

音频录制覆盖 Capturer 会话、输入流处理、服务端 source、麦克风和播放采集策略、EC 相关处理、音效面板触发的音效链，以及 HDI 输入设备适配。

## 设计规格

- 按采集用途、来源、格式、采样和声道要求建立输入会话；策略确认来源与目标输入设备后，由服务执行采集流。
- source 承接服务端输入流，管理数据产生、缓冲区交付和输入端生命周期；其状态需与采集会话和设备状态一致。
- HDI 适配层连接输入设备能力，处理能力协商、开始停止、设备变化及错误恢复。
- 录制数据可经过受控的前处理链；EC 等回声控制处理应由场景、设备和功能能力共同决定，不能假定所有录制流都启用。
- 音效面板相关音效链属于特定产品或场景能力。面板状态、策略状态和音频处理链应保持协调，关闭或不可用时须有明确降级行为。
- 支持普通输入、受控播放采集及仓库启用的其他采集源；采集策略必须区分来源和授权边界。

## 约束与常见误区

- 区分 Capturer 生命周期、audio_service 的采集执行、source 的输入承接、audio_policy 的来源与设备决策，以及 HDI 设备适配。
- 读取长度、帧对齐、阻塞模式、缓冲区所有权和会话状态必须校验；来源切换后不得交付旧来源残留数据。
- EC 和音效面板音效链是有条件的场景处理，不应与所有录音路径耦合，也不能绕过用户或系统策略。
- 播放采集不是麦克风采集的别名；必须遵守用途过滤、目标应用选择和授权限制。
- source 或硬件输入失效时，应停止交付无效数据并有序释放资源；不可用状态不能伪装成成功采集。

## 安全与隐私

- 麦克风权限、系统隐私开关、设备封锁、账户状态和调用方身份必须在可信服务边界校验。
- 播放采集需执行调用方授权、用途限制和用户选择规则；拒绝后不能保留后台采集。
- EC、音效链和诊断处理不得记录或导出原始录音数据及敏感特征。
- 服务端状态与权限不一致时失败关闭，不因客户端请求而跳过策略检查。
