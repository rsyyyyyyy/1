# 音频播放

## 范围

音频播放覆盖 Renderer 会话、输出流处理、服务端 sink、下游音频处理和硬件适配。播放策略决定流能否发声及目标设备；播放执行层维护流状态、数据提交和输出端资源；HDI 适配层连接系统音频设备能力。

## 设计规格

- 按用途和场景建立播放会话，协商格式、采样、声道、缓冲和时延要求。
- 支持写入或回调驱动的数据提交，以及暂停、恢复、排空、刷新、停止和释放等生命周期操作。
- sink 负责承接服务端输出流、消费音频帧并协调下游处理和设备输出；其可用状态与流状态应一致。
- HDI 适配负责将框架侧输出能力映射到硬件接口，并处理能力协商、启动停止、错误返回及设备状态变化。
- 设备切换、服务恢复和输出能力变化时，应按策略重新绑定或恢复会话，不把某种设备路径视为所有产品的固定实现。

## 约束与常见误区

- 区分音频策略的设备决策、音频流管理的流执行、sink 的输出承接和 HDI 的设备适配职责。
- 启动、写入、暂停、停止和释放必须遵守会话状态；停止或释放后不得继续消费旧缓冲区。
- 写入长度、帧对齐、共享缓冲区所有权、背压和部分提交必须明确处理。
- sink、处理链和 HDI 资源应按建立顺序的逆序释放；设备断开或服务不可用时不能继续使用失效句柄。
- 低时延、卸载、直通等路径受产品能力、设备能力和构建选项限制，不可描述为通用保证。
- 不要把设备适配成功等同于物理设备已经稳定发声；端点、路由和策略状态仍需联合确认。

## 安全与隐私

- 特权用途和受限输出能力必须校验调用方身份及授权。
- 仅传递接口契约需要的数据；日志和转储不得暴露 PCM、令牌、未脱敏身份或设备地址。
- 对元数据、缓冲区描述和适配层错误进行边界校验；失败时保持状态一致并释放可回收资源。
