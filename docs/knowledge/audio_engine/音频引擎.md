# 音频引擎

## 范围

音频引擎负责服务端音频处理能力的组织与执行，涵盖 `services/audio_engine/` 的处理图、缓冲区、管理、插件和调度机制，以及 `frameworks/native/audioeffect/` 的在线音效接入边界。

## 设计规格

- 依照流参数和策略配置组织处理节点与处理链，完成格式适配、音效和其他受支持的实时处理。
- 引擎管理层协调会话、节点、缓冲区和处理资源的生命周期。
- 插件用于扩展处理能力；在线音效接口表达客户端请求，具体执行能力由策略、引擎和设备能力共同决定。
- 处理链应支持能力协商、初始化、运行、参数更新、异常处理和释放。
- 基础处理路径应能在可选节点或插件不可用时按产品策略降级。

## 约束与常见误区

- 音频引擎是处理执行层，不等同于设备路由、通路选择或音效 API 门面。
- 节点输入输出格式、通道布局、帧数、时序和缓冲区所有权必须兼容。
- 实时处理避免无界分配、不可预测阻塞和不受控锁竞争；处理失败不能破坏其他会话状态。
- 插件和节点须有清晰的创建、参数更新、失效和销毁边界；不能跨生命周期复用失效资源。
- 不要把特定产品的音效节点或插件能力描述为所有设备的固定能力。
- 【铁律】VOIP低时延/DIRECT播放的音量是在HAL层处理，在音频框架中只将音量设置到对应sink即可，不需要对数据进行音量计算，即需要创建的是HpaeVolumeSyncNode，一定不能创建HpaeGainNode，否则会导致在音频框架和HAL各计算一次音量，从而出现音量变小的问题

## 安全与隐私

- 音效参数、插件输入和缓冲区描述均需校验；越界或不兼容请求应拒绝或降级。
- 插件边界须检查失败返回并确保资源回收。
- 日志、跟踪和转储不得包含原始 PCM、用户内容或可识别个人的音频特征。
