# 音频性能和内存

## 范围

本主题涵盖实时音频的时限与调度约束、DDL 管理、线程优先级、任务调度、ROM/RAM 占用及内存回收（reclaim）行为。

## 设计规格

- 实时音频处理需在目标时限内完成；DDL 用于表达处理期限和超期风险，不是允许任意延迟的缓冲策略。
- 线程优先级和调度策略应匹配任务实时性、负载和系统资源，并受平台策略约束。
- 缓冲区容量、队列深度和预分配策略需在时延、吞吐和内存占用之间平衡。
- 内存评估区分常驻代码和只读资源（ROM）与运行时堆、共享缓冲区及映射（RAM），覆盖典型并发会话和异常恢复峰值。
- reclaim 相关行为需考虑活动音频资源的可回收性、重新创建成本和时延目标；资源淘汰与会话生命周期应协调。

## 约束与常见误区

- 不能通过无限增大缓冲区掩盖 DDL 违约或调度饥饿。
- 优先级提升必须有范围和恢复策略；不能长期占用高优先级造成系统其他任务饥饿。
- 实时线程避免阻塞 I/O、长时间锁持有、无界内存分配和不可控回收。
- 不能仅用单流或空闲态数据代表 RAM；需考虑多流、音效链、设备切换、服务重启和并发峰值。
- reclaim 或内存压力路径不得让正在使用的缓冲区失效；无法保留资源时应执行明确的停止、降级或重建流程。
- ROM/RAM 数据需与产品配置、功能开关和构建变体对应，不能混用不同构建结果。

## 安全与隐私

- 内存回收和转储不得把音频内容遗留在可被非授权主体读取的区域。
- 共享内存映射需验证边界、长度、所有权和释放时序。
- 性能诊断只采集分析所需指标，不输出 PCM、用户内容或不必要身份信息。
