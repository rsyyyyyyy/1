# 音频会话

## 范围

AudioSession 负责跨客户端流生命周期的协调，提供两类能力：通过 AudioSessionStrategy 影响系统基础焦点策略，以及申请应用级全局焦点。AudioSession 同时承载会话级场景、状态回调、去激活原因、设备管理和行为标志等公共契约。焦点策略与响应动作的内部实现见 [音频焦点管理.md](../audio_interrupt/音频焦点管理.md)。

## 设计规格

### AudioSession 的两类功能

AudioSession 提供两类能力，可单独使用策略影响模式，也可在策略影响模式基础上叠加应用级全局焦点模式：

**策略影响模式**：应用通过 AudioSessionStrategy 声明并发偏好，影响系统对该应用音频流的基础焦点仲裁规则。此模式下焦点仍由各音频流启动时单独申请，AudioSessionStrategy 不替流持有焦点，只改变仲裁语义。应用内所有音频流默认受 AudioSessionStrategy 影响；生效有一定约束条件：设置为 CONCURRENCY_MIX_WITH_OTHERS 时只对同类型音频流生效（如媒体与媒体之间）；应用声明的并发模式不能比系统默认策略更严格——例如系统默认策略为 PAUSE 别人时，CONCURRENCY_PAUSE_OTHERS 才可生效；系统默认策略为 DUCK 别人时，CONCURRENCY_PAUSE_OTHERS 不生效。总体原则：AudioSessionStrategy 只能把更严格的系统默认策略放宽为更宽松的策略，不能反向收紧。

**应用级全局焦点模式**：应用通过 AudioSession 申请应用级全局焦点，单个音频流启动时不再单独申请焦点，复用会话级焦点。当会话级焦点被打断、暂停或闪避时，应用内所有受影响范围内的音频流一并响应。此模式下已设置的 AudioSessionStrategy 同样生效，仲裁规则与会话级焦点叠加作用。此模式同样有作用范围限制：录音、通知音等不受会话级焦点影响，仍独立申请焦点。

应用级全局焦点模式叠加在策略影响模式之上；无论是否启用会话级焦点，已设置的 AudioSessionStrategy 均生效，不应将两类功能视为互斥。不从实现推断跨版本保证。

### 并发偏好

AudioSessionStrategy 通过并发模式声明应用的让位语义（@since 12）：默认、与其他混播（MIX_WITH_OTHERS）、闪避其他（DUCK_OTHERS）、暂停其他（PAUSE_OTHERS）。混播模式允许共存，闪避/暂停模式对应内部闪避让位/暂停让位策略，详见 [音频焦点管理.md](../audio_interrupt/音频焦点管理.md)。

### 场景

场景枚举（@since 20）：媒体、游戏、语音通话、语音留言；场景影响流用途、焦点协同、设备策略和状态通知，仅在相应能力和策略条件成立时生效。

### 生命周期与去激活

- 会话建立、属性更新、激活、释放和恢复必须在策略与流执行之间保持一致。
- 会话空闲超时、后台处理和应用退出清理属于不同生命周期条件，不可相互替代。
- 会话去激活原因（@since 12）：低优先级被抢占（LOWER_PRIORITY）和超时（TIMEOUT）；去激活后 AudioSessionStrategy 失效，若焦点通过设置场景获取，则需重新设置场景才能再次取焦。

### 状态回调

- 公共状态提示：恢复、暂停、停止、超时停止（TIME_OUT_STOP，@since 20）、闪避（DUCK）、取消闪避（UNDUCK）、静音建议（MUTE_SUGGESTION，@since 23）、取消静音建议（UNMUTE_SUGGESTION，@since 23）、静音（MUTE，@since 24）、取消静音（UNMUTE，@since 24）。
- 客户端通过状态回调了解策略结果；流状态变化应回馈会话管理，以便后续请求重新评估。
- 静音建议与强制静音不同：建议由应用自行决定是否执行，强制静音由系统直接生效。混播模式下默认不下发静音，仅当应用启用静音建议后才下发建议提示（@since 23）。

### 会话级设备管理

- 会话级设备管理（@since 20/21）：会话 API 提供默认输出设备设置、媒体输入设备选择、可用设备查询与监听、当前输入/输出设备变化回调，以及蓝牙与近链路偏好录音类别；行为详见 [音频路由和发声规则.md](../audio_routing_rules/音频路由和发声规则.md) 和 [音频设备管理.md](../audio_device_manager/音频设备管理.md)。
- 设备变化建议动作（@since 20）：输出设备变化时下发建议继续或建议停止，由应用决定后续行为。

### 行为标志

会话行为标志（@since 24）：应用可声明被中断时的响应偏好（中断时静音 MUTE_WHEN_INTERRUPTED、中断时暂停 PAUSE_WHEN_INTERRUPTED），对应内部静音让位/暂停让位策略；标志为空表示清除设置，不改变既有行为。

## 约束与常见误区

- 不要把焦点申请成功当作设备已选定或音频已实际输出。
- 会话状态和 Renderer/Capturer 流状态是相关但不同的状态模型。
- 过期回调不能恢复已经停止、释放或失去授权的流；会话标识必须绑定正确调用方。
- 设备切换、服务重启和账户变化后应重新评估适用会话，不假设原决策永久有效。
- 策略影响模式可单独使用；应用级全局焦点模式叠加在策略影响模式之上，已设置的 AudioSessionStrategy 在两种模式下均生效，不应将两类功能视为互斥。
- 场景状态或回调注册并不代表会话始终激活；必须考虑超时、退后台、无活动流及显式释放。
- 焦点策略属于全局协调，单一应用的请求可能影响其他流，必须考虑确定性和公平性。
- 策略影响模式下，不在影响范围内的音频流（如录音、通知音）仍按自身焦点逻辑运行，不应假设 AudioSessionStrategy 对应用所有流都生效。
- 应用级全局焦点模式下，不受会话级焦点影响的音频流（如录音、通知音）仍独立申请焦点，不应假设会话级焦点覆盖应用所有流。

## 安全与隐私

- 特殊会话请求需校验调用者身份、用途和权限。
- 对应用只暴露其自身及接口契约要求的会话状态；不泄露其他应用不必要的身份和活动信息。
- 回调仅携带完成状态同步所需的数据，并校验远程对象和会话有效性。
