# 音频框架目录结构说明

下表说明本仓库主要目录及其子目录职责。测试模糊目标数量较多，按目标族归纳；每个具体模糊测试目录通常都包含独立的 GN 目标、测试入口和可选工程元数据。

## 知识库目录

`docs/knowledge/` 按职责分为五类，主题文档名称保持稳定，目录用于表达其归属层次：

| 知识库目录 | 归属范围 | 主题内容 |
| --- | --- | --- |
| `common/` | 公共 | DFX、性能与内存、安全隐私、测试与故障诊断等跨模块规则。 |
| `audio_policy/` | 音频策略 | 设备管理、多音区、路由和发声规则、音频会话、音量等全局策略。 |
| `audio_stream/` | 音频流管理 | Renderer、Capturer、pipe 选择及流生命周期和数据通路管理。 |
| `audio_engine/` | 音频引擎 | 引擎处理图、节点、插件和在线音效。 |
| `audio_suite/` | 音频编创 | `audio_suite` 相关的编创接口、服务能力和配置边界。 |

知识库目录分类表达文档的主要责任域，不代表源码目录一一对应。跨层任务应先阅读责任域文档，再根据文档中的源码入口检查协作边界。
