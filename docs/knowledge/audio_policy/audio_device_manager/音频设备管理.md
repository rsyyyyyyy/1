# 音频设备管理

## 范围

音频设备管理负责设备发现、描述、能力状态、连接生命周期和变化通知，覆盖输入输出设备、本地和分布式设备，以及蓝牙、USB、有线、星闪（NearLink）、助听、虚拟（VA）等接入类别。

本主题只管设备"是什么、是否在线、是否可用、是否激活"；设备选择和场景路由规则见 [音频路由和发声规则.md](../audio_routing_rules/音频路由和发声规则.md)，通路选择见 [通路选择.md](../../audio_stream/audio_pipe_selector/通路选择.md)，权限与隐私边界见 [安全与隐私.md](../../common/security_privacy/安全与隐私.md)。

## 设计规格

### 整体结构与协作链

设备管理域为单例集群，所有核心管理器进程级唯一，构造时通过引用相互持有。事件纵向流转：

1. 外部事件源（HDI/蓝牙/USB/PnP/分布式/VA/SLE）产生设备事件。
2. 事件监听器进行协议解析与事件去重。
3. 排他锁串行化所有状态变更回调。
4. 业务编排中心协调设备列表维护与回调下发，并触发路由重选（路由决策本身见 [音频路由和发声规则.md](../audio_routing_rules/音频路由和发声规则.md)，pipe 管理见 [通路选择.md](../../audio_stream/audio_pipe_selector/通路选择.md)）。
5. 设备行为工厂按设备类型创建并缓存行为对象，执行激活/去激活。

### 通用设备能力（设备描述符）

设备描述符承载"需要支持的通用设备能力"。
约束标记：**必须**（所有设备均须维护）、**可选**（有默认值或按需设置）、**特定**（仅特定设备类型或场景才设置）。

### 通用麦克风能力

麦克风描述符维护以下能力，生成实现时需维护：

- 已连接麦克风描述符列表：设备连接/断开时增删。
- 采集会话-麦克风映射：采集会话启动/停止时关联/解除，支持按会话 ID 批量解除。
- 临时静音（运行时）与持久静音（跨重启）分离管理；启动期恢复持久静音；USB-ARM 连接时恢复静音状态。

### 通用设备属性定义（audio_device_privacy.xml）

设备按隐私属性分为三类，由 XML 配置文件定义，支持产品级覆盖（产品可放置自定义 XML 于高优先级路径，取第一个匹配文件，不支持增量合并）。

| 属性 | 含义 | 包含设备 |
|---------|------|-------------|
| `privacy` | 隐私设备（声音仅佩戴者可收听，麦克风仅近距离人声） | 有线耳机、TWS/头戴蓝牙耳机、星闪耳机、助听器 |
| `public` | 公共设备（声音向外扩散，存在音频外泄风险） | 本机扬声器、外接音箱、DP/HDMI、车机/音箱类蓝牙 |
| `negative` | 消极设备（不主动用于该场景，如已连接但未佩戴的耳机） | 未佩戴耳机、手表类蓝牙、Accessory、特定 HDMI/Line |

**设备匹配规则**：设备连接时，按设备类型 + 设备角色 + 设备类别 + 设备用途四字段组合匹配隐私归属。同一设备类型可因类别不同归入不同属性（如蓝牙 A2DP：耳机/眼镜类→privacy、音箱/车机类→public、未佩戴耳机类→negative），实际归属由设备上报的类别决定。

### 设备接入方式与能力差异

不同设备类型的接入（发现/连接）方式与能力差异：

| 类别 | 接入方式 | 能力差异 |
|------|---------|---------|
| 内置（EARPIECE/SPEAKER/MIC/WAKEUP） | 启动期加载 primary 模块时一并建立，不在线时单独加载 | 单实例（硬件唯一） |
| 有线 PnP（WIRED/USB/DP/HDMI/ACCESSORY/MICIN） | netlink uevent 或 `/sys/class/switch/*` 或 HDI 服务状态变更 → PnP 服务（受有线检测开关控制）→ 事件监听器解析 | 类型修正（USB_HIFI→USB_ARM、EXTERN_CABLE 断开=耳机断开）；DP/USB_ARM/ACCESSORY 走本地设备加载建端口，其余复用 primary |
| USB-ARM | USB 系统服务/CommonEvent → USB 管理器扫描声卡 → 上报后策略层修正为 USB_ARM | 按角色单活动地址；EC 特性路径输入不开端口；buffer 按 20ms 重算；采样率降精度 |
| 蓝牙 A2DP | 蓝牙系统服务 → 蓝牙客户端媒体管理器 → 全局设备观察者 | 双向独立 module（`a2dp`/`a2dp_input`）；可选绝对音量；双蓝牙活动集合；设备切换走 module reload |
| 蓝牙 SCO | 蓝牙系统服务 → 蓝牙客户端 HFP 管理器 → 全局设备观察者 | 用 HFP 配置文件；按 audioMode 分流；天然双向；失败置异常 + 重算 |
| 蓝牙助听 | 复用 A2DP 通路（无独立蓝牙客户端封装） | 仅输出；固定 16kHz 低采样率；绑定通话音量类型；单实例守卫 |
| 星闪 SLE | 星闪音频系统服务回调 → 星闪设备管理器 | 流类型级并发（非设备级）；双连失败降级；分布式终止→挂起连接；卡拉OK loopback 启动静音 1.2s |
| 虚拟 VA | VA 设备控制器 IPC 远程代理 → VA 设备管理器（死亡监听自动清理） | 单向 SPP/双向 SPP/双向 Nearlink；懒适配器生命周期；单向影响 SCO 麦克风独占；支持降噪模式 |
| 分布式 | dAudio HDI → 事件监听器解析 model 协议（hicar/hiplay） | 按 networkId 隔离设备；分布式能力二次上报合并；分布式不可用 reason 触发静音过渡 |

**设备行为分发映射**（设备行为工厂）：SCO→SCO 行为、A2DP→A2DP 行为、NEARLINK/NEARLINK_IN→星闪行为、USB_ARM_HEADSET→ARM 行为、HEARING_AID→助听行为；其他类型返回空（直接成功，按"无特殊行为"激活，复用 primary 通路）。

### 设备上下线流程

**上线（连接）核心规格**：
1. 类型修正：特殊设备类型按规则映射为实际类型。
2. 构造设备描述符并更新分组信息（焦点组、音量组、能力集合、本地网络标识）。
3. 去重：移除同标识的已存在设备。
4. 按类型加载 HDI 模块：部分类型立即建端口，部分类型仅登记配置待激活时建端口，内置/有线等启动期已建。
5. 加入连接设备列表、分类列表、麦克风描述符列表；更新隐私类型（未佩戴耳机强制隐私）、显示名、音量。
6. 触发设备变更回调与可用设备变更回调。
7. 触发路由重选，路由决策见 [音频路由和发声规则.md](../audio_routing_rules/音频路由和发声规则.md)。

**下线（断开）核心规格**：
1. 从连接设备列表、分类列表、麦克风描述符列表移除；清理首选设备和流设备信息。
2. 触发设备变更回调与可用设备变更回调。
3. 触发路由重选（**必须先触发路由重选再卸载 HDI 模块，避免悬空 sink**）。
4. 按类型卸载 HDI 模块、关端口、清活跃设备。

**关键不变量**：连接时"先加载 HDI 模块再更新列表"；断开时"先触发路由重选再卸载 HDI 模块"。

**分布式特殊规格**：上线时按 hdiPin 映射设备类型，同类型已连仅更新能力（分布式能力可能二次上报需合并）。下线时清理流属性、停流、挂起设备、清理设备映射、卸载代理、关端口。支持批量下线清理所有非本地设备。

### 连接状态管理

设备描述符的连接状态（`connectState_`）表示设备与系统之间的链路关系，决定设备是否可被路由选用。各状态定义如下：

| 状态 | 含义 | 物理设备 | 链路情况 | 使用前是否需触发建链 |
|------|------|---------|---------|-------------------|
| `CONNECTED` | 已连接，正常可用 | 存在 | 通信链路和数据链路均已建立 | 否 |
| `VIRTUAL_CONNECTED` | 虚拟连接 | 存在 | 无实际通信链路 | 是，需先触发建立通信链路 |
| `DEACTIVE_CONNECTED` | 去激活连接（仅 SCO 设备） | 存在 | HFP 配置文件已连接，数据链路未建立 | 是，需先触发数据链路建立 |
| `SUSPEND_CONNECTED` | 挂起连接 | 存在 | 链路均正常，因冲突等原因暂时不可用 | 否（恢复冲突解除即可） |
| `SIMULATED_CONNECTED` | 模拟连接 | 不存在 | 无物理链路，存在逻辑通路 | 否 |

**`SIMULATED_CONNECTED` 特殊约束**：无实际物理设备但存在逻辑通路，框架在无真实设备时默认选择该设备。该状态在设备创建时确定，随设备生命周期固定不变，不支持切换到其他连接状态。跨 IPC 序列化时映射为 `INVALID`，不暴露给外部。

**连接状态转换规格**：

| 转换 | 触发条件 | 说明 |
|------|---------|------|
| 初始 → `SIMULATED_CONNECTED` | 设备创建时判定为模拟设备 | 固定状态，不再转换 |
| 初始 → `CONNECTED` | 设备上线（正常连接路径） | 大多数设备类型的默认初始状态 |
| 初始 → `VIRTUAL_CONNECTED` | 分布式音箱/音乐主机/蓝牙/星闪上线 | 初始被发现让用户感知设备存在，但不实际建立通信连接 |
| 初始 → `DEACTIVE_CONNECTED` | SCO 设备 HFP 连接但未建立音频链路 | 仅 SCO 设备 |
| `CONNECTED` → `VIRTUAL_CONNECTED` | 真实设备断开但保留虚拟占位 | 同类型已存在虚拟设备时，真实设备退为虚拟 |
| `VIRTUAL_CONNECTED` → `CONNECTED` | 真实设备接入替换虚拟占位 | 设备上线时移除同标识虚拟条目 |
| `CONNECTED` → `SUSPEND_CONNECTED` | 星闪分布式用户终止；SCO 分布式用户终止 | 链路仍在但暂停使用 |
| `SUSPEND_CONNECTED` → `CONNECTED` | 清除星闪挂起状态 | 星闪设备恢复 |
| `SUSPEND_CONNECTED` → `DEACTIVE_CONNECTED` | 清除 SCO 挂起状态 | SCO 设备恢复为去激活（需再建数据链路） |
| `DEACTIVE_CONNECTED` → `CONNECTED` | SCO 音频数据链路建立 | SCO 设备激活音频通路 |

**路由过滤规则**：`VIRTUAL_CONNECTED`、`SUSPEND_CONNECTED` 状态的设备不参与路由选择；`DEACTIVE_CONNECTED` 状态的 SCO 设备在路由决策时需触发数据链路建立后可用；`SIMULATED_CONNECTED` 设备在无其他可用设备时作为默认选择。

### 设备激活/去激活规格

**激活规格**：设备激活由流路由决策触发，携带目标设备描述符和变更原因（新设备可用/旧设备不可用/覆盖/场景设置/分布式不可用等）。激活时按设备类型匹配对应行为对象执行激活操作；未覆盖的设备类型直接成功（复用 primary 通路）。

**冲突互斥**：仅当流已启动时触发跨类型冲突互斥。星闪与（A2DP+SCO）双向互斥——激活一方时去激活另一方。同类型冲突规则见"同类型设备的并发约束"。

**幂等性**：已激活设备重复激活时，相同设备直接返回成功，不重复建端口；不同设备同类型激活时按类型规则处理（切换式或共存）。

**去激活规格**：
- 按设备类型去激活：用于冲突互斥和类型级释放，清除该类型所有已激活记录。
- 按设备描述符去激活：用于设备断开和定向释放，按设备 ID 精确清除。
- 去激活行为因设备类别而异（空操作/清活动/关端口/重置计数），不可统一假设。

**失败回滚**：激活失败时回滚目标设备为旧设备，置异常标记，返回重取设备原因，上层收到后重新触发路由重选。端口开失败时恢复当前活动端口并触发路由重选。

### SCO 管理

SCO（同步面向连接）设备通过 HFP 配置文件接入，天然双向（输入+输出），单活动设备。

**SCO 类别**：SCO 连接按业务场景区分为以下类别，决定 SCO 音频参数和路由优先级：

| 类别 | 含义 | 典型场景 |
|------|------|---------|
| 蜂窝通话（CALLULAR） | 蜂牙电话通话 | 蜂窝语音通话 |
| 虚拟通话（VIRTUAL） | VoIP 虚拟通话 | 第三方 VoIP 应用通话 |
| 语音识别（RECOGNITION） | 语音识别采集 | 语音助手唤醒/识别 |
| 默认（DEFAULT） | 未分类 | 初始/兜底状态 |

**SCO 状态机**：SCO 连接生命周期由状态机管理，状态间转换受超时控制（默认 3 秒）：

| 状态 | 含义 |
|------|------|
| INIT | 初始状态，SCO 未启动 |
| DISCONNECTED | 已断开，无 SCO 链路 |
| CONNECTING | 连接中，正在建立 SCO 链路 |
| CONNECTED | 已连接，SCO 链路可用 |
| DISCONNECTING | 断开中，正在释放 SCO 链路 |

**状态转换规格**：

| 转换 | 触发条件 | 说明 |
|------|---------|------|
| INIT → DISCONNECTED | 初始化完成 | 进入待命状态 |
| DISCONNECTED → CONNECTING | 收到 SCO 连接请求 | 携带类别参数；启动 3 秒超时计时 |
| CONNECTING → CONNECTED | HFP SCO 链路建立成功 | 清除超时计时 |
| CONNECTING → DISCONNECTED | 超时未建立 | 清除超时计时；执行缓存请求（如有） |
| CONNECTED → DISCONNECTING | 收到 SCO 断开请求 | 开始释放链路 |
| DISCONNECTING → DISCONNECTED | HFP SCO 链路释放完成 | 执行缓存请求（如有） |

**请求缓存机制**：在 CONNECTING 或 DISCONNECTING 状态期间收到的新连接/断开请求会被缓存，待状态转换完成后按序执行。同一设备同一类别的重复连接请求直接返回成功（幂等）；不同类别的连接请求触发类别切换（先断开当前 SCO 再以新类别连接）。

**SCO 类别切换规则**：当前已连接 SCO 的类别与新请求类别不同时，需先断开当前 SCO 连接再以新类别重新连接；类别相同时无需切换。切换过程中缓存的请求在断开完成后执行。

**与连接状态的联动**：SCO 设备的 `connectState_` 与 SCO 状态机独立但关联——HFP 连接但未建立 SCO 音频链路时设备为 `DEACTIVE_CONNECTED`，SCO 音频链路建立后转为 `CONNECTED`，分布式用户终止时转为 `SUSPEND_CONNECTED`。

### 同类型设备的并发约束

| 设备类型 | 是否支持连接多个同类设备 | 是否支持多个同类设备同时使用 | 同时使用的能力范围 |
|---------|----------------------|--------------------------|-----------------|
| A2DP | 是 | 是（双蓝牙） | 双蓝牙可同时激活，各自独立通路；仅车机形态支持 |
| SCO | 是 | 否 | 同一时刻仅单活动 HFP 设备 |
| USB-ARM | 是 | 否 | 同一角色同一时刻仅单活动地址 |
| 星闪 SLE | 是 | 部分 | 同一时刻仅单活动设备，但同一设备多流类型/多会话可并存 |
| 助听 | 否 | 否 | 硬件单实例 |
| 分布式 | 是 | 是 | 多设备可同时激活，按 networkId 隔离 |
| 内置 | 否 | 否 | 硬件单实例 |

### 不同设备类型使用时的冲突管理

**跨类型冲突规则**：

| 冲突对 | 规则 | 层级 |
|--------|------|------|
| 星闪 ↔ (A2DP+SCO) | 双向互斥；激活星闪去激活 A2DP+SCO，激活 A2DP/SCO 去激活星闪；仅流已启动时触发 | 工厂级 |
| A2DP offload ↔ 普通 A2DP | 同设备判定在 offload 状态变化时返回不一致，触发重新取设备 | 设备比较层 |

通路层面的并发冲突（Fast/Offload 切换、Fast 流超限、Modem 通信流等）见 [通路选择.md](../../audio_stream/audio_pipe_selector/通路选择.md)。

**单向 VA 设备与 SCO 麦克风独占性联动**：单向 VA 设备接入/使能时构造 SCO 输入描述符，标记"SCO 麦克风独占不可用"，经设备信息更新上报。影响 SCO 输入路由可用性。

### 设备恢复机制

服务重启后从持久化存储读取首选设备（媒体渲染/通话渲染/铃声渲染/提示音渲染/通话采集/录音采集/识别采集）和排除设备列表，重放选择/排除操作。约束：先恢复流（首次等 1 秒）再恢复设备；最大重试 5 次，间隔递增（300ms）；虚拟设备触发真实蓝牙/星闪连接。

### 设备信息查询与监听回调

**查询维度**：支持按以下维度组合查询已连接设备：

| 查询维度 | 说明 |
|---------|------|
| 设备类型 | 按单一或多种 DeviceType 筛选 |
| 设备角色 | 按输出/输入筛选 |
| 隐私属性 | 按 privacy/public/negative 筛选 |
| 设备用途 | 按媒体/通话/识别用途位掩码筛选 |
| 设备标志 | 按本地/蓝牙/分布式等设备标志筛选 |

查询返回设备描述符，包含"通用设备能力"章节中定义的对外字段。

**监听回调**：支持以下场景的设备变化回调，回调内容为变更后的设备描述符：

| 回调场景 | 触发时机 | 回调信息 |
|---------|---------|---------|
| 设备连接/断开 | 蓝牙/有线/星闪/分布式/VA 设备上下线 | 设备描述符（含连接状态、设备类型、角色、地址等） |
| 设备配置变更 | 设备能力变化（如 A2DP 编解码变化） | 设备描述符（含更新后的流信息、能力集合等） |
| 设备信息更新 | 设备类别/连接状态/使能/用途/异常标记变化 | 设备描述符（含更新后的对应字段） |
| 麦克风阻塞 | 麦克风物理阻塞/解除 | 设备类型、阻塞状态 |
| 设备强制/隐私选择 | 强制设备选择或隐私设备选择触发 | 设备类型、地址、调用方信息 |
| HDI 服务状态 | HDI 服务上下线 | 服务索引、连接状态 |
| 连接失败 | 设备连接失败 | 设备描述符、失败信息 |

### 基础设施层定位

infra 层是策略服务的"跨系统服务接入层"，**不包含设备策略决策**，只提供配置、IPC 代理、数据共享、状态监控、窗口感知等基础设施。依赖方向单向：设备域 → infra，infra 不反向依赖设备域。包含：配置（XML 配置 + 解析器）、IPC 代理（设备变更回调下发客户端、端口加载/卸载代理）、数据共享（系统设置项读写）、应用客户端（应用前后台/长时任务感知）。

## 约束与常见误区

- 设备管理说明设备"是什么、是否可用"；设备选择和场景路由规则由独立策略模块负责。
- 设备连接不等于已成为活动设备；设备可用也不代表所有流格式都兼容。
- 热插拔事件可能重复、过期或乱序，处理时应校验当前设备状态并避免重复资源释放。
- 分布式设备需区分本地和分布式身份、授权及生命周期；分布式能力可能二次上报需合并。
- 蓝牙、USB、有线、星闪、助听和虚拟设备不能被假设为拥有完全相同的能力或恢复行为。
- 已连接设备列表是连接状态的唯一权威来源；分类列表是其投影，必须保持一致；新增设备类型/类别必须同步更新隐私属性 XML。
- 所有观察者回调必须先经设备状态锁加排他锁，不可绕过锁直接调用编排中心。
- 星闪与（A2DP+SCO）双向互斥；A2DP 与 SCO 不互斥；其他类型不参与工厂级互斥。冲突互斥仅流已启动时触发。
- 管理器为单例且构造时相互引用持有，初始化顺序敏感，不可在构造函数中调用未初始化单例的方法。
- 日志中的 MAC 地址和networkId必须脱敏，不得输出原始 MAC和networkId。
- 去激活行为因设备类别差异极大（空操作/清活动/关端口/重置计数），不可统一假设。
- 断开时必须"先触发路由重选再卸载 HDI 模块"，避免悬空 sink；连接时"先加载 HDI 模块再更新列表"。
- 复用通用判定函数，不要自定义类型判定逻辑。

## 安全与隐私

- 设备地址、网络标识和账户偏好属于敏感信息，应限制访问和诊断输出；MAC 地址和networkId需脱敏。
- 蓝牙设备的设备名称和 MAC 地址为 public 字段，但调用方须持有 `ohos.permission.USE_BLUETOOTH` 权限，否则序列化时返回空字符串。
- 网络标识、焦点组 ID、音量组 ID 为 system 字段，仅系统应用可获取；非系统应用序列化时网络标识返回空、组 ID 返回无效值（-1）。
- 分布式设备操作需验证授权和当前可信状态。
- 输入设备封锁、隐私状态和设备能力必须在实际采集或输出前再次确认。
- 蓝牙 HDI 服务停止且 A2DP 仍连接时主动退出策略服务以触发重启恢复，避免悬空状态。
- 单向 VA 设备接入会影响 SCO 麦克风可用性，需联动更新独占标记。
- inner 字段（设备类别、连接状态、用途、音量、异常标记等）不暴露给应用层，仅用于系统 SA 间 IPC 传递。
