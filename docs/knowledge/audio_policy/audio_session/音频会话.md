# 音频会话

## 范围

音频会话负责跨客户端流生命周期的协调，包含音频焦点、中断、共存、闪避、暂停/停止和恢复，以及 Audio Session V2 相关会话能力。焦点是会话协调的一部分，不代表完整会话模型。

## 设计规格

- 会话以受控身份和用途参与协调，音频策略根据活动会话及系统场景决定是否共存、闪避、中断、暂停或拒绝。
- 客户端通过状态通知了解策略结果；流状态变化应回馈会话管理，以便后续请求重新评估。
- Audio Session V2 涉及会话策略、场景属性、激活与释放、会话状态回调、焦点协同和超时管理；相关状态变化需与流活动状态及应用前后台状态协调。
- V2 场景信息可影响会话中的流用途、焦点协同、设备策略和状态通知；仅在相应能力和策略条件成立时生效。
- 会话建立、属性更新、激活、释放和恢复必须在策略与流执行之间保持一致。
- 会话空闲超时、后台处理和应用退出清理属于不同生命周期条件，不可相互替代。
- 设备、账户、服务和应用状态变化可触发会话策略重评估。

## 约束与常见误区

- 不要把焦点申请成功当作设备已选定或音频已实际输出。
- 会话状态和 Renderer/Capturer 流状态是相关但不同的状态模型。
- 过期回调不能恢复已经停止、释放或失去授权的流；会话标识必须绑定正确调用方。
- 设备切换、服务重启和账户变化后应重新评估适用会话，不假设原决策永久有效。
- Audio Session V2 与旧有协调路径不得混用属性语义；按能力和接口契约选择，不从实现推断跨版本保证。
- V2 场景状态或回调注册并不代表会话始终激活；必须考虑超时、退后台、无活动流及显式释放。
- 焦点策略属于全局协调，单一应用的请求可能影响其他流，必须考虑确定性和公平性。

## 安全与隐私

- 特殊会话请求需校验调用者身份、用途和权限。
- 对应用只暴露其自身及接口契约要求的会话状态；不泄露其他应用不必要的身份和活动信息。
- 回调仅携带完成状态同步所需的数据，并校验远程对象和会话有效性。
